# Private Channel Invitation Policy

## 1. 목표

비공개 채널의 초대와 참여 규칙을 명확히 정의해, API 구현과 Web UX가 같은 기준을 따르도록 합니다.

이 문서는 현재 프로젝트에서 사용할 확정 정책을 다룹니다.

## 2. 핵심 원칙

- 비공개 채널은 멤버만 접근할 수 있습니다.
- 비공개 채널은 공개 채널 참여 API로 참여할 수 없습니다.
- 비공개 채널 참여는 초대 기반으로만 가능합니다.
- 초대 권한은 채널 관리자에게만 부여합니다.
- 초대 요청이 성공하면 대상 사용자는 즉시 채널 멤버로 추가됩니다.

## 3. 접근 정책

### 비공개 채널 목록 노출

- 비공개 채널은 해당 채널 멤버에게만 목록에 노출됩니다.
- 멤버가 아닌 사용자는 채널 ID를 알고 있어도 목록에서 볼 수 없습니다.

### 비공개 채널 상세 조회

- 비공개 채널 상세 정보는 멤버만 조회할 수 있습니다.
- 멤버가 아닌 사용자가 조회하면 `404 Not Found` 또는 동일한 수준의 비노출 응답을 반환합니다.

### 비공개 채널 메시지 조회

- 비공개 채널 메시지는 멤버만 조회할 수 있습니다.
- 읽음 상태 갱신도 멤버만 수행할 수 있습니다.

## 4. 역할 정책

### 관리자(`admin`)

- 채널 생성자는 최초 `admin`입니다.
- `admin`은 비공개 채널에 사용자를 초대할 수 있습니다.
- 추후 필요하면 관리자 추가/해제 정책을 확장할 수 있습니다.

### 일반 멤버(`member`)

- `member`는 채널 메시지 조회 및 작성은 가능하지만, 다른 사용자를 초대할 수 없습니다.
- `member`는 별도 정책이 생기기 전까지 관리자 권한을 가질 수 없습니다.

## 5. 초대 정책

### 초대 가능 조건

- 요청자는 인증된 사용자여야 합니다.
- 대상 채널은 비공개 채널이어야 합니다.
- 요청자는 해당 비공개 채널의 멤버여야 합니다.
- 요청자는 해당 비공개 채널에서 `admin` 역할이어야 합니다.
- 초대 대상은 존재하는 활성 프로필이어야 합니다.

### 초대 처리 방식

초대 요청이 성공하면 대상 사용자를 즉시 `channel_members`에 추가합니다.

1. 채널 존재 여부 확인
2. 채널이 비공개인지 확인
3. 요청자의 해당 채널 멤버십과 역할 확인
4. 초대 대상 프로필 존재 여부 확인
5. 이미 멤버인지 확인
6. 멤버가 아니면 `channel_members`에 `member`로 추가

### 중복 초대 처리

- 이미 채널 멤버인 사용자를 다시 초대해도 에러로 처리하지 않습니다.
- 이 경우 idempotent 하게 성공 응답을 반환합니다.

### 자기 자신 초대

- 요청자가 자기 자신을 초대하는 경우는 새 동작이 없으므로 no-op 성공 또는 `400 Bad Request` 중 하나를 선택할 수 있습니다.
- 현재 정책에서는 구현 단순성을 위해 no-op 성공 처리도 허용 가능합니다.

## 6. 참여 정책

### 참여 가능 방식

- 비공개 채널은 초대를 통해서만 참여할 수 있습니다.
- `POST /channels/:channelId/join` 같은 공개 참여 API로는 참여할 수 없습니다.

### 참여 시점

- 초대가 완료되는 순간 참여가 확정됩니다.
- 초대받은 사용자는 별도 수락 절차 없이 즉시 채널 멤버가 됩니다.

## 7. 권장 API 설계

### 비공개 채널 초대 API

- 메서드: `POST`
- 경로: `/channels/:channelId/invitations`
- 요청 바디 예시:
  - `userId`

### 동작

- 요청자가 `admin`이면 대상 사용자를 해당 비공개 채널 멤버로 추가합니다.
- 응답은 갱신된 채널 정보 또는 초대된 멤버 정보를 반환할 수 있습니다.

### 권장 응답 규칙

- 채널 없음: `404 Not Found`
- 비공개 채널이 아님: `400 Bad Request` 또는 `409 Conflict`
- 요청자가 멤버가 아님: `404 Not Found` 또는 `403 Forbidden`
- 요청자가 `admin`이 아님: `403 Forbidden`
- 대상 프로필 없음: `404 Not Found`
- 이미 멤버임: `200 OK`
- 신규 초대 성공: `200 OK` 또는 `201 Created`

## 8. UI/UX 기준

### 초대 버튼 노출

- 비공개 채널에서만 초대 UI를 노출합니다.
- 현재 사용자가 `admin`일 때만 초대 버튼을 보여줍니다.

### 초대 대상 선택

- 사용자 검색 결과에서 현재 채널 멤버는 제외하거나, 이미 멤버임을 표시합니다.
- 삭제된 사용자나 비활성 사용자는 선택할 수 없게 합니다.

### 초대 완료 후 반영

- 초대 성공 시 채널 멤버 목록이 즉시 갱신되어야 합니다.
- 초대받은 사용자는 채널 목록에 해당 비공개 채널이 노출되어야 합니다.

## 9. 서버 구현 메모

- 권한 검사는 Web이 아니라 API에서 최종적으로 수행해야 합니다.
- 비공개 채널 접근 제어는 상세 조회, 메시지 조회, 읽음 상태, 첨부 파일 접근까지 일관되게 적용해야 합니다.
- 초대 API는 idempotent 하게 만드는 편이 재시도와 UX에 유리합니다.
- 장기적으로는 감사 로그 또는 system message로 "누가 누구를 초대했는지" 남길 수 있습니다.
