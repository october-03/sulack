# Product Overview

## 1. 프로젝트 한 줄 설명

Sulack은 회사 내부에서 사용하는 프라이빗 메신저를 목표로 하는 Slack 레퍼런스 기반 학습 프로젝트입니다.

## 2. 프로젝트 목적

이 프로젝트는 메신저 서비스를 처음부터 끝까지 직접 구현해 보면서, 특히 Supabase의 핵심 기능을 실전 맥락에서 익히는 데 목적이 있습니다.

핵심 학습 포인트는 아래와 같습니다.

- `Auth`: 사용자 로그인, 세션 관리, 앱 사용자 정보 연결
- `Realtime`: 채널/DM 메시지 실시간 반영
- `Storage`: 파일 업로드, 다운로드, 접근 정책 설계
- `PostgreSQL`: 메시지 서비스에 적합한 데이터 모델 설계
- `NestJS + Prisma`: 도메인 로직과 DB 접근 계층 구성

## 3. 제품 가정

- 단일 회사 내부 구성원만 사용하는 서비스입니다.
- 외부 공개 가입은 없고, 사내 사용자만 접근 가능합니다.
- 멀티 워크스페이스 개념은 제외합니다.
- 조직도, 부서, 고급 관리자 기능은 초기 범위에서 제외합니다.

즉, Slack의 "한 회사 안에서 쓰는 협업 채팅"에 집중하고, 워크스페이스 멀티테넌시는 다루지 않습니다.

## 4. 타겟 사용자

- 사내 개발팀
- 소규모 협업 조직
- Supabase 기반 협업 서비스 구조를 학습하려는 팀

## 5. 핵심 사용자 시나리오

### 시나리오 A. 로그인 후 채널에 참여한다

1. 사용자는 회사 계정으로 로그인한다.
2. 채널 목록을 확인한다.
3. 공개 채널에 입장하거나 비공개 채널에 초대받는다.
4. 채널 메시지를 읽고 새 메시지를 보낸다.

### 시나리오 B. 동료와 1:1 DM을 주고받는다

1. 사용자는 동료를 검색한다.
2. 기존 DM이 있으면 이어서 대화한다.
3. 없으면 새 DM 방을 생성한다.
4. 상대방이 보낸 메시지를 실시간으로 수신한다.

### 시나리오 C. 파일을 업로드한다

1. 사용자는 채널 또는 DM에서 파일을 첨부한다.
2. 파일은 Supabase Storage에 업로드된다.
3. 메시지에는 파일 메타데이터와 접근 URL이 연결된다.
4. 같은 대화방 참여자는 파일을 조회할 수 있다.

## 6. MVP 범위

### 포함

- 사내 사용자 인증
- 사용자 프로필
- 채널 생성 및 참여
- 공개 채널 / 비공개 채널
- 1:1 DM
- 메시지 작성 / 수정 / 삭제
- 실시간 메시지 수신
- 파일 업로드
- 읽음 상태 관리

### 제외 또는 후순위

- 멀티 워크스페이스
- 오디오/화상 통화
- 봇/앱 연동
- 스레드의 고도화 기능
- 검색 최적화
- 고급 알림 정책
- 관리자 콘솔

## 7. 제품 성공 기준

아래 기준을 만족하면 1차 목표를 달성한 것으로 봅니다.

- 로그인한 사용자가 채널과 DM에서 메시지를 안정적으로 주고받을 수 있다.
- 새 메시지가 화면에 실시간으로 반영된다.
- 첨부 파일이 안전하게 업로드되고 같은 대화 참여자에게만 노출된다.
- 기본적인 읽음 상태가 동작한다.
- Supabase Auth, Realtime, Storage, PostgreSQL 사용 흐름을 프로젝트 코드에서 명확히 확인할 수 있다.
