# Functional Requirements

## 1. 인증

### 목표

Supabase Auth를 사용해 사내 사용자의 로그인과 세션을 처리합니다.

### 요구사항

- 사용자는 이메일 기반으로 로그인할 수 있어야 합니다.
- 필요 시 magic link 또는 OTP 기반 로그인도 고려할 수 있어야 합니다.
- 로그인한 사용자는 앱 내 프로필 정보와 연결되어야 합니다.
- 인증되지 않은 사용자는 채팅 기능에 접근할 수 없어야 합니다.

### 구현 메모

- Auth의 사용자 ID를 앱의 `profiles` 테이블과 1:1로 연결합니다.
- 앱 내부 로직은 `auth.users` 직접 조회보다 `profiles` 중심으로 읽도록 설계합니다.

## 2. 사용자 프로필

### 요구사항

- 사용자는 표시 이름, 프로필 이미지, 상태 메시지를 가질 수 있어야 합니다.
- 사용자는 자신 프로필을 수정할 수 있어야 합니다.
- 채널/DM 목록과 메시지 목록에서 발신자 정보를 볼 수 있어야 합니다.

## 3. 채널

### 요구사항

- 사용자는 공개 채널을 생성할 수 있어야 합니다.
- 사용자는 비공개 채널을 생성할 수 있어야 합니다.
- 채널에는 이름, 설명, 생성자, 공개 여부가 있어야 합니다.
- 채널 참여자만 해당 채널 메시지를 볼 수 있어야 합니다.

### 세부 정책

- 공개 채널은 회사 사용자라면 자유롭게 참여할 수 있습니다.
- 비공개 채널은 초대받은 사용자만 참여할 수 있습니다.

## 4. DM

### 요구사항

- 사용자는 다른 사용자와 1:1 DM을 시작할 수 있어야 합니다.
- 같은 두 사용자 사이의 1:1 DM은 중복 생성되지 않아야 합니다.
- DM 참여자만 해당 대화 내용을 볼 수 있어야 합니다.

## 5. 메시지

### 요구사항

- 사용자는 채널과 DM에 메시지를 작성할 수 있어야 합니다.
- 사용자는 자신이 작성한 메시지를 수정할 수 있어야 합니다.
- 사용자는 자신이 작성한 메시지를 삭제할 수 있어야 합니다.
- 메시지는 작성자, 본문, 생성 시각, 수정 시각을 가져야 합니다.

### 후순위 확장

- 스레드 답글
- 멘션
- 이모지 리액션
- 메시지 고정

## 6. 실시간 기능

### 요구사항

- 같은 채널 또는 DM에 새 메시지가 올라오면 실시간으로 반영되어야 합니다.
- 메시지 수정/삭제도 실시간으로 반영되어야 합니다.
- 읽음 상태 변경도 실시간 UI 갱신 대상이 될 수 있어야 합니다.

### 구현 메모

- Supabase Realtime 구독 단위는 메시지, 읽음 상태, 참여자 변경을 기준으로 설계합니다.
- 초기에는 메시지 중심으로 시작하고, 읽음 상태는 후속 단계에서 확장합니다.

## 7. 파일 첨부

### 요구사항

- 사용자는 메시지에 파일을 첨부할 수 있어야 합니다.
- 업로드된 파일은 Supabase Storage에 저장되어야 합니다.
- 파일 메타데이터는 DB에 저장되어야 합니다.
- 대화 참여자만 파일에 접근할 수 있어야 합니다.

### 파일 메타데이터 예시

- 원본 파일명
- 저장 경로
- MIME 타입
- 파일 크기
- 업로더
- 연결된 메시지 ID

## 8. 읽음 상태

### 요구사항

- 사용자는 각 채널/DM에서 마지막으로 읽은 메시지 시점을 저장할 수 있어야 합니다.
- 채널/DM 목록에서 읽지 않은 메시지 여부를 표현할 수 있어야 합니다.

### 구현 메모

- 정교한 unread count보다 `last_read_message_id` 또는 `last_read_at` 기반 접근으로 시작합니다.

## 9. 검색

### MVP 기준

- 사용자 검색
- 채널 검색

### 후순위

- 메시지 전문 검색
- 파일 검색

## 10. 권한 및 보안

### 요구사항

- 인증되지 않은 요청은 차단되어야 합니다.
- 채널/DM 참여 여부에 따라 메시지 조회 권한이 제한되어야 합니다.
- 파일 접근도 대화 참여자 기준으로 제한되어야 합니다.
- 서버와 DB 정책이 서로 중복 검증하도록 설계해야 합니다.
